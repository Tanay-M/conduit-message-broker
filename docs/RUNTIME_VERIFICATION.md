# Conduit runtime verification

Executed on 13 October 2026. This supersedes the runtime limitation recorded during the earlier static review. Product source, schema files, and broker queries were not modified.

## Docker failure and recovery

The Docker client was installed, but the backend crashed before creating `dockerDesktopLinuxEngine`. The startup log identified the failure while renaming `C:\Users\asus\AppData\Local\Docker\run\sailor-ingest.sock` to a stale socket name. Windows returned error 1920, “The file cannot be accessed by the system.” WSL2 distributions were present; this was not evidence of a missing WSL2 installation.

A recent [report in the Codex repository](https://github.com/openai/codex/issues/52698) describes this signature when processes inherit packaged-app filesystem virtualization. This report is supporting evidence, not a maintainer-confirmed diagnosis for this machine. Our successful intervention was to stop the failed Docker processes and launch the installed Docker Desktop executable through Windows Explorer instead of directly from the agent shell. No socket files, Docker data disks, volumes, or WSL registrations were removed.

The original `docker version` connection check then succeeded and reported engine 29.7.2. Docker access from the restricted shell required approved execution outside the sandbox after startup.

`docker compose up -d --build` rebuilt the current source and started the database and API. The original `conduit_conduit_pgdata` volume was retained. Initialization SQL does not automatically rerun against that existing volume, so clean SQL checks used separate temporary databases initialized from the current files.

The five defects were driven through the actual running SQL functions, HTTP handlers, and HTML templates. The timestamp probe submits the same sequence shape generated by the browser JavaScript; it does not constitute an interactive browser-button test.

Passing existing tests and demos therefore does not remove the readiness issues. Their fixtures use small sequences, monitoring checks mainly assert HTTP success, and the partial-ack demo exercises a favorable returned prefix rather than arbitrary completion order.

- Performance benchmarks were not rerun. Retained historical benchmark numbers remain historical.
- No interactive browser click-through, full arbitrary-SQL adversarial security test, or exhaustive concurrency test completed beyond the actual existing suites and specified probes.
- No scenario application, new business schema, replacement deck, or product bug fixes were implemented. Those follow agreement on the demonstration and an explicitly scoped implementation step.

The main project remains available at `http://localhost:8000`. Use the existing app/admin login paths. Keep Docker running for subsequent work; the launch route through Explorer resolved the startup failure in this session.
